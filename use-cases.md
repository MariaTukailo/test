# Спецификации вариантов использования (Use Cases)

## UC-001: Создание комнаты мероприятия

*   **Актор:** Организатор.
*   **Краткое описание:** Пользователь создает новое мероприятие для планирования.
*   **Предусловия:** Пользователь авторизован в системе.
*   **Основной поток:**
    1. Пользователь нажимает кнопку «Создать мероприятие».
    2. Система отображает форму ввода (название, дата, описание, место).
    3. Пользователь заполняет данные и нажимает «Сохранить».
    4. Система создает уникальную «комнату» и перенаправляет на её страницу.
*   **Альтернативный поток (А1):** Если обязательные поля не заполнены, система выводит сообщение об ошибке валидации и не создает комнату.
*   **Постусловия:** Комната создана, Организатор получает доступ к управлению.

## UC-002: Генерация ссылки-приглашения

*   **Актор:** Организатор.
*   **Краткое описание:** Организатор создает ссылку для приглашения гостей и участников команды.
*   **Предусловия:** Комната создана, пользователь находится на странице комнаты.
*   **Основной поток:**
    1. Организатор нажимает кнопку «Пригласить».
    2. Система генерирует уникальную ссылку.
    3. Система отображает ссылку и кнопку «Скопировать».
*   **Постусловия:** Ссылка создана и готова к отправке.

## UC-003: Ведение чек-листа задач

*   **Актор:** Участник команды.
*   **Краткое описание:** Член команды добавляет задачу в чек-лист подготовки к мероприятию.
*   **Предусловия:** Пользователь авторизован и имеет доступ к комнате.
*   **Основной поток:**
    1. Участник команды переходит в раздел «Чек-лист».
    2. Нажимает кнопку «Добавить задачу».
    3. Вводит название задачи и назначает ответственного.
    4. Нажимает «Сохранить».
    5. Задача появляется в общем списке со статусом «Не выполнено».
*   **Альтернативный поток (А1):** Если название задачи пустое, система выводит ошибку валидации.
*   **Постусловия:** Задача добавлена в чек-лист.

## UC-004: Управление бюджетом

*   **Актор:** Организатор.
*   **Краткое описание:** Организатор вносит статьи расходов и фиксирует затраты.
*   **Предусловия:** Пользователь авторизован, комната создана.
*   **Основной поток:**
    1. Организатор переходит в раздел «Бюджет».
    2. Нажимает кнопку «Добавить расход».
    3. Вводит название статьи и запланированную сумму.
    4. Система добавляет статью в смету и пересчитывает остаток бюджета.
*   **Альтернативный поток (А1):** Если введена отрицательная сумма или текст, система выдает ошибку.
*   **Постусловия:** Статья расходов добавлена в смету.

## UC-005: Просмотр комнаты мероприятия (Гость)

*   **Актор:** Участник (Гость).
*   **Краткое описание:** Гость открывает комнату по ссылке-приглашению для просмотра информации.
*   **Предусловия:** Гость перешел по валидной ссылке-приглашению.
*   **Основной поток:**
    1. Система открывает страницу комнаты.
    2. Гость видит описание мероприятия, дату, дресс-код, карту и список участников.
    3. Гость может подтвердить участие (RSVP).
*   **Альтернативный поток (А1):** Если ссылка устарела, система отображает сообщение «Приглашение недействительно».
*   **Постусловия:** Гость ознакомлен с информацией о мероприятии.

## UC-006: Добавление в виш-лист

*   **Актор:** Участник (Гость).
*   **Краткое описание:** Гость добавляет пожелание в общий список подарков.
*   **Предусловия:** Гость находится в комнате мероприятия.
*   **Основной поток:**
    1. Гость переходит в раздел «Виш-лист».
    2. Вводит текст пожелания (например, «Книга»).
    3. Нажимает «Добавить».
    4. Пожелание отображается в списке с указанием автора.
*   **Альтернативный поток (А1):** Если строка пустая или превышает 200 символов, система выдает ошибку.
*   **Постусловия:** Пожелание сохранено в виш-листе.

## UC-007: Интеграция с календарем

*   **Актор:** Участник (Гость) или Организатор.
*   **Краткое описание:** Пользователь добавляет мероприятие в свой личный календарь.
*   **Предусловия:** Пользователь находится на странице комнаты.
*   **Основной поток:**
    1. Пользователь нажимает кнопку «Добавить в календарь».
    2. Система генерирует `.ics` файл.
    3. Браузер скачивает файл.
    4. Пользователь открывает файл, и событие добавляется в его календарь (Google Calendar, Apple Calendar и т.д.).
*   **Альтернативный поток (А1):** Если генерация файла не удалась, система выводит сообщение об ошибке.
*   **Постусловия:** Мероприятие добавлено в календарь пользователя.

## UC-008: Просмотр интерактивной карты

*   **Актор:** Участник (Гость).
*   **Краткое описание:** Гость просматривает место проведения на карте.
*   **Предусловия:** Гость находится в комнате, место проведения указано.
*   **Основной поток:**
    1. Гость видит виджет карты с установленной меткой.
    2. При клике на метку отображается точный адрес.
*   **Альтернативный поток (А1):** Если картографический сервис недоступен, система показывает текстовый адрес и сообщение «Карта временно недоступна».
*   **Постусловия:** Гость ознакомлен с местом проведения.
